## 📖 Conceito: Por que um Design System?

Um **Design System** não é apenas uma biblioteca de componentes; é a "única fonte de verdade" (**Single Source of Truth**) visual e funcional de um produto. No MergeSkills, utilizamos um sistema baseado no **Material Design 3**, mas com a personalidade rústica e tecnológica da marca.

### O que são Design Tokens?

São as menores unidades de design. Em vez de usar valores "hardcoded" (como `#4CDF20` ou `fontSize: 16`), usamos **nomes semânticos**.
- **Vantagem:** Se mudarmos o tom de verde da marca, alteramos em um único lugar (`Colors.ts`) e todo o app se atualiza.
- [Referência:] Consulte `lddm-specs/design/tokens/` para as especificações originais.

## 🏗️ Anatomia de um Componente Profissional

Para entender como o **[StitchButton.tsx](file:///merge-skills-react/components/StitchButton.tsx)** funciona, vamos "desmontá-lo" e analisar cada linha sob a ótica do desenvolvimento profissional.

### 1. O Contrato: `StitchButtonProps`
Antes de escrever a lógica, definimos as **Props** (Propriedades). No TypeScript, usamos uma `interface` para criar um contrato de segurança:

```typescript
interface StitchButtonProps {
  text: string;      // O que será exibido no botão (Obrigatório)
  onClick: () => void; // A função que será executada ao clicar (Obrigatório)
  enabled?: boolean;  // Opcional: define se o botão pode ser clicado
  loading?: boolean;  // Opcional: define se o botão está processando
}
```
> **Por que usar?** Isso garante que, se você esquecer de passar o `text` ao usar o botão, o VS Code mostrará um erro na hora, antes mesmo de você rodar o app.

### 2. A Estrutura: `React.FC<StitchButtonProps>`
`FC` significa *Functional Component*. Ao declarar `export const StitchButton: React.FC<StitchButtonProps> = (...)`, estamos dizendo ao React: 
- "Este é um componente funcional que segue o contrato definido em `StitchButtonProps`".

### 3. O Componente de Toque: `TouchableOpacity`
Diferente do `<Button />` nativo (que é limitado e difícil de estilizar), o `TouchableOpacity` nos dá controle total:
- **`activeOpacity`**: Define o quão "apagado" o botão fica ao ser pressionado (usamos `0.8` para um feedback visual suave).
- **Flexibilidade**: Ele aceita uma lista de estilos (`style={[styles.button, { backgroundColor }, style]}`), permitindo que o visual mude dinamicamente de acordo com o estado do botão.

### 4. Inteligência e Feedback (Haptics)
Dentro da função `handlePress`, injetamos inteligência:
```tsx
const handlePress = () => {
    if (enabled && !loading) {
        Haptics.impactAsync(Haptics.ImpactFeedbackStyle.Medium); // Feedback tátil
        onClick(); // Executa a ação do usuário
    }
};
```
Isso garante que o botão só vibre e execute a ação se ele estiver **ativado** e **não estiver carregando**, evitando múltiplos cliques acidentais.

### 5. Renderização Condicional (Ternário)
No retorno (JSX), usamos uma condicional para decidir o que mostrar:
- **`loading ? <ActivityIndicator /> : <Text />`**
Se `loading` for verdadeiro, mostramos o "girador" de carregamento; caso contrário, mostramos o texto do botão. Isso melhora drasticamente a percepção de performance do app.

## 💻 Implementação no Código

### 1. Sistema de Cores e Tematização

O arquivo `constants/Colors.ts` centraliza a paleta **StitchGreen**. Ele foi projetado para suportar **Light** e **Dark Mode** nativamente.

```tsx title="constants/Colors.ts"
export default {
  light: {
    primary: '#4CDF20',    // StitchGreen
    background: '#F5F5F7',
    surface: '#FFFFFF',
    onSurface: '#1C1C1E',
  },
  dark: {
    primary: '#4CDF20',
    background: '#0F0F0F',
    surface: '#1C1C1E',
    onSurface: '#E5E5E5',
  },
};
```

### 2. Escalas Tipográficas

Utilizamos duas fontes principais via Google Fonts:
- **Outfit**: Para títulos e destaques (`bold`, `semi-bold`).
- **Inter**: Para corpos de texto e labels de interface.

Estas escalas são mapeadas em `constants/Typography.ts`, seguindo as 15 variantes do Material3 (Display, Headline, Title, Body, Label).

### 3. Componente Atômico: StitchButton

O `StitchButton` é nosso primeiro componente "premium". Ele segue regras estritas de acessibilidade e design:
- **Altura Fixa**: `56dp` (ideal para toque).
- **Feedback Tátil**: Usa `expo-haptics` para vibrar levemente ao ser clicado.
- **Estados**: Suporta `loading` e `disabled` com transparências específicas (`12%` para desativado).
