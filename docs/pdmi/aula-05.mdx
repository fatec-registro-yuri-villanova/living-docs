## 🌿 Fluxo de Navegação

O app agora abre diretamente na tela de Login. Após o submit (simulado nesta aula), o usuário é redirecionado para o **Showcase** (`index.tsx`) via `router.replace('/')`.

```
[ Login ] ──→ (submit) ──→ [ Showcase / FlatList ]
```

A configuração do Stack vive em `app/_layout.tsx`:

```tsx title="app/_layout.tsx"
<Stack screenOptions={{ headerShown: false }}>
  {/* login é a primeira rota — abre ao iniciar o app */}
  <Stack.Screen name="login" />
  <Stack.Screen name="index" />
</Stack>
```

:::tip Por que `router.replace` ao invés de `router.push`?
- `router.push('/') ` → mantém o Login na pilha de navegação (usuário pode voltar com o botão físico).
- `router.replace('/')` → **substitui** o Login pelo Showcase. O usuário não consegue "voltar" para o Login depois de entrar. ✅
:::

## 📖 Recapitulação: `useState`

O **`useState`** é o Hook do React mais importante. Ele permite que um componente "lembre" de informações entre renderizações.

```tsx
// Sintaxe básica
const [valor, setValor] = useState(valorInicial);
//     ↑            ↑            ↑
//  variável    função setter   estado inicial
```

### Como Funciona em Formulários (Controlled Components)

```tsx
const [email, setEmail] = useState('');

// Fluxo completo ao digitar "a":
// 1. Usuário pressiona "a" no teclado
// 2. onChangeText é chamado com o texto atual
// 3. setEmail("a") atualiza o estado
// 4. React re-renderiza o componente
// 5. TextInput exibe "a" (valor vem do estado, não do DOM)

<TextInput
  value={email}            // ← lê do estado
  onChangeText={setEmail}  // ← escreve no estado
/>
```

:::tip Controlled vs Uncontrolled
- **Controlled** (`useState`): React é a fonte da verdade → fácil de validar ✅
- **Uncontrolled** (`useRef`): o DOM é a fonte da verdade → difícil de validar ❌
:::

## 📦 Estrutura de Componentes

Nesta aula, todos os componentes ficam em arquivos separados dentro de `components/`:

```
components/
  ├── ColorBox.tsx        ← amostra de cor (Showcase)
  ├── Section.tsx         ← bloco de seção (Showcase)
  ├── StitchButton.tsx    ← botão (Aula 04)
  ├── StitchCard.tsx      ← card de lista  ← NOVO
  └── StitchTextField.tsx ← input de formulário ← NOVO
```

:::caution Organização é obrigatória
Componentes definidos **inline** dentro de telas (ex: `const Section = ...` dentro de `index.tsx`) são difíceis de reusar e testar. Cada componente deve ter seu **próprio arquivo** em `components/`.
:::

## 💻 Novos Componentes

### `StitchCard` — Container para Listas

```tsx title="components/StitchCard.tsx"
interface StitchCardProps {
  children: React.ReactNode;
  onPress?: () => void;       // torna o card clicável
  containerColor?: string;    // cor de fundo customizada
}
```

**Uso em `FlatList`:**

```tsx
<FlatList
  data={cursos}
  keyExtractor={(item) => item.id}
  renderItem={({ item }) => (
    <StitchCard onPress={() => console.log(item.title)}>
      <Text>{item.title}</Text>
      <Text>{item.description}</Text>
    </StitchCard>
  )}
/>
```

### `StitchTextField` — Input com Estado Visual

```tsx title="components/StitchTextField.tsx"
interface StitchTextFieldProps {
  label: string;
  value: string;                          // conectado ao useState
  onValueChange: (text: string) => void;  // setter do useState
  placeholder?: string;
  isError?: boolean;                      // borda vermelha
  errorMessage?: string;                  // texto abaixo do campo
  secureTextEntry?: boolean;              // para senhas
  keyboardType?: KeyboardTypeOptions;
}
```

**Uso com validação:**

```tsx
const [senha, setSenha] = useState('');

<StitchTextField
  label="Senha"
  value={senha}
  onValueChange={setSenha}
  secureTextEntry
  isError={senha.length > 0 && senha.length < 6}
  errorMessage="Mínimo 6 caracteres"
/>
```

### `KeyboardAvoidingView` — Ergonomia Mobile

Evita que o teclado cubra os campos:

```tsx
<KeyboardAvoidingView
  behavior={Platform.OS === 'ios' ? 'padding' : 'height'}
  style={{ flex: 1 }}
>
  {/* Formulário aqui */}
</KeyboardAvoidingView>
```

:::caution Comportamento por Plataforma
- **iOS**: `behavior="padding"` empurra o conteúdo para cima.
- **Android**: `behavior="height"` reduz a altura do container.
:::

### Validação de e-mail em tempo real

Adicione validação de formato de e-mail com `regex` no `StitchTextField`:

```tsx
const emailRegex = /^[^\s@]+@[^\s@]+\.[^\s@]+$/;
const isEmailValid = emailRegex.test(email);

<StitchTextField
  label="E-mail"
  value={email}
  onValueChange={setEmail}
  isError={email.length > 0 && !isEmailValid}
  errorMessage="Digite um e-mail válido"
/>
```

Adicione um `useState` extra para alternar `secureTextEntry`:

```tsx
const [showPassword, setShowPassword] = useState(false);

<StitchTextField
  label="Senha"
  value={password}
  onValueChange={setPassword}
  secureTextEntry={!showPassword}
/>
<TouchableOpacity onPress={() => setShowPassword(p => !p)}>
  <Text>{showPassword ? 'Ocultar senha' : 'Mostrar senha'}</Text>
```
