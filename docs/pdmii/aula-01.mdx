## 💻 Código de Referência

### 1. Val e Var — Variáveis Mutáveis e Imutáveis

`val` só pode ser atribuída uma vez; `var` pode ser reatribuída. Regra prática: **comece sempre com `val`** e só troque para `var` quando o compilador reclamar.

```kotlin title="basics/Topico01Variaveis.kt"
fun entendendoVariaveis() {
    // val (Value): variável IMUTÁVEL
    val pi: Double = 3.14
    val nomeDoCurso = "Merge Skills: Android Nativo"   // Inferência de tipo

    // var (Variable): variável MUTÁVEL
    var count: Int = 0
    count = 1 // Permitido

    // pi = 3.14159  // ERRO de compilação — val não pode ser reatribuída

    // Tipagem explícita vs. inferência
    val cargaHoraria: Int = 40
    val valorDaMensalidade: Double = 99.90
    val possuiCertificado: Boolean = true
    val inicialDoNome: Char = 'M'
}
```

### 2. Null Safety — Proteção contra NullPointerException

Em Kotlin o **tipo já diz** se o valor pode ser nulo: `String` nunca é nulo, `String?` pode ser. O compilador obriga você a tratar o segundo caso.

```kotlin title="basics/Topico02NullSafety.kt"
fun lidandoComNulos() {
    var nome: String = "João"           // Non-nullable: nunca pode ser null
    var sobrenome: String? = null       // Nullable: pode ser null

    // Safe Call `?.`: só executa se sobrenome não for nulo
    val tamanho: Int? = sobrenome?.length

    // Elvis Operator `?:`: retorna valor padrão caso a variável seja nula
    val tamanhoNaoNulo: Int = sobrenome?.length ?: 0

    // Exemplo do projeto: campo de GitHub do usuário
    var githubDoProfessor: String? = null
    val linkSeguro = githubDoProfessor ?: "Não Cadastrado"
}
```

### 3. Funções

```kotlin title="basics/Topico03Funcoes.kt"
// Função tradicional com parâmetros e retorno
fun sayHello(name: String) {
    println("Olá, $name!")
}

// Sintaxe de expressão (single-expression function)
fun somarModerno(a: Int, b: Int) = a + b

// Função com valores padrão nos parâmetros
fun saudar(nome: String, saudacao: String = "Olá") {
    println("$saudacao, $nome!")
}
```

Valores padrão evitam criar várias sobrecargas da mesma função. E argumentos nomeados deixam a chamada legível: `saudar(saudacao = "Boa noite", nome = "Ana")`.

### 4. Controle de Fluxo — if, when e Loops

Detalhe que muda tudo: em Kotlin, `if` e `when` são **expressões** — devolvem valor. Por isso a linguagem não tem operador ternário: o próprio `if` já faz esse papel.

```kotlin title="basics/Topico04ControleDeFluxo.kt"
fun controleDeFluxo(notaMedia: Double) {
    // IF como expressão (retorna valor)
    val status = if (notaMedia >= 7.0) "Aprovado" else "Reprovado"

    // WHEN: o Switch-Case potente do Kotlin
    when (notaMedia) {
        10.0           -> println("Aluno Perfeito!")
        in 7.0..9.9    -> println("Aprovado com folga")
        else           -> println("Precisamos estudar mais")
    }

    // FOR em coleção
    val tecnologias = listOf("Kotlin", "Jetpack Compose", "Coroutines", "Koin")
    for (tech in tecnologias) {
        println("Aprenderemos: $tech")
    }
}
```

### 5. Coleções — List, Set, Map

Kotlin separa a coleção **imutável** (`listOf`, `setOf`, `mapOf`) da **mutável** (`mutableListOf`, …). Prefira sempre a imutável: ela não pode ser alterada por engano em outro ponto do código.

```kotlin title="basics/Topico05Colecoes.kt"
fun exemploColecoes() {
    // LIST: coleção ordenada, permite duplicatas
    val nomes = listOf("João", "Maria", "Pedro")    // Imutável
    val notas = mutableListOf(8, 7, 9)              // Mutável
    notas.add(10)                                   // [8, 7, 9, 10]

    // SET: coleção de itens únicos, desordenada
    val frutas = setOf("Maçã", "Banana", "Morango", "Maçã")
    // frutas conterá apenas "Maçã", "Banana", "Morango" (sem duplicata)

    // MAP: pares chave-valor, chaves únicas
    val idades = mapOf("João" to 30, "Maria" to 25)
    val alunos = mutableMapOf<String, Int>()
    alunos["Pedro"] = 28
}
```

### 6. Higher-Order Functions e Lambdas

Uma **higher-order function** é a que recebe outra função como parâmetro. `map`, `filter` e `forEach` são os exemplos que você mais vai usar. `it` é o nome implícito do único parâmetro do lambda.

```kotlin title="basics/Topico06LambdasEHof.kt"
fun exemploHigherOrderFunctions() {
    val numeros = listOf(1, 2, 3, 4)
    val quadrados = numeros.map { it * it }       // [1, 4, 9, 16]

    val todoNumeros = listOf(1, 2, 3, 4, 5, 6)
    val pares = todoNumeros.filter { it % 2 == 0 } // [2, 4, 6]

    // Encadeamento de operações (pipeline funcional)
    numeros
        .filter { it > 2 }      // [3, 4]
        .map { it * 10 }        // [30, 40]
        .forEach { println(it) }
}
```

A vantagem: em vez de descrever **como** percorrer a coleção (`for`, índice, acumulador), você descreve **o que** quer dela.

### 7. OOP — Classes e Data Classes

`class` tem comportamento; `data class` existe para **carregar dados**. O compilador gera de graça `equals()`, `hashCode()`, `toString()` e `copy()` — por isso ela é o tipo natural para respostas de API e itens de lista.

```kotlin title="basics/Topico07ClassesEDataClasses.kt"
class AlunoNormal(val nome: String, val idade: Int) {
    fun apresentar() {
        println("Olá, me chamo $nome e tenho $idade anos.")
    }
}

// Data class: usada para representar dados (ex: respostas de API)
data class Curso(
    val id: Int,
    val titulo: String,
    val descricao: String
)
```

### 8. Herança, Polimorfismo e Interfaces

Em Kotlin toda classe é **final por padrão**: para permitir herança, marque a classe e cada método sobrescrevível como `open`. Isso é proposital — herança só onde foi projetada.

```kotlin title="basics/Topico08HerancaEInterfaces.kt"
open class UsuarioPlataforma(val id: Int, val nickname: String) {
    open fun autenticar() {
        println("Autenticando via email e senha padrão...")
    }
}

class AlunoPremium(
    id: Int,
    nickname: String,
    val beneficiosVip: Boolean
) : UsuarioPlataforma(id, nickname) {

    override fun autenticar() {
        super.autenticar()
        println("Acesso VIP Liberado instantaneamente!")
    }
}

// Interface: define um contrato de ações
interface NavegadorDeCursos {
    fun abrirAula(id: Int)
    fun finalizarCurso()
}
```

**Polimorfismo** é a consequência prática: uma lista de `UsuarioPlataforma` pode conter os dois tipos, e cada item executa a *sua* versão de `autenticar()` — sem `if`, sem checagem de tipo.

### Exercício 01 — Cálculo de IRRF

O RH precisa estimar o Imposto de Renda a partir do salário bruto. O campo é **opcional**: o valor pode não ser informado.

1. Crie a função `calcularIrrf(salarioBruto: Double?): Double`.
2. Quando o salário não for informado, o cálculo considera `0.0`.
3. A função deve ter um **único ponto de saída**, e a alíquota deve ser determinada em **um único lugar**.
4. Não é permitido o operador `!!`.

| Faixa salarial | Alíquota |
|----------------|----------|
| Até R$ 2.259,20 | Isento (0%) |
| De R$ 2.259,21 até R$ 2.826,65 | 7,5% |
| Acima de R$ 2.826,65 | 15% |

| Entrada | Saída esperada |
|---------|----------------|
| `2000.0` | R$ 0,00 |
| `2500.0` | R$ 187,50 |
| `5000.0` | R$ 750,00 |
| `null` | R$ 0,00 |

**Conceito:** operador elvis para tratar a ausência de valor; `when` sem argumento para escolher a alíquota em um único ponto.

### Exercício 02 — Fatura de energia com bandeira tarifária

A distribuidora aplica bandeira vermelha quando o consumo mensal ultrapassa o limite.

1. Implemente `calcularFatura(consumoKwh: Double, precoKwh: Double): Double`.
2. O corpo da função deve caber em **uma única linha, sem chaves e sem variáveis auxiliares**.
3. Consumo **acima** de 150 kWh recebe acréscimo de 10%.
4. O limite é **exclusivo**: exatamente 150 kWh não recebe acréscimo.

| Consumo (preço do kWh = R$ 0,85) | Saída esperada |
|----------------------------------|----------------|
| `100.0` | R$ 85,00 |
| `150.0` | R$ 127,50 |
| `200.0` | R$ 187,00 |

**Conceito:** função de expressão única, com `if` usado como expressão dentro do próprio cálculo.

### Exercício 03 — Validador de segurança de token

Antes de liberar acesso a uma API, o app precisa validar a chave recebida, que pode não existir.

1. Crie `validarAcesso(token: String?): String`.
2. Acesso é `"Autorizado"` somente se o token existir **e** tiver mais de 10 caracteres.
3. Nos demais casos, a mensagem deve **diferenciar as duas falhas**: token ausente × token curto demais.
4. Não é permitido `!!` nem `try/catch`.

| Entrada | Saída esperada |
|---------|----------------|
| `"abc123xyz789"` | Autorizado |
| `"abc123"` | Alerta: token muito curto |
| `null` | Alerta: token ausente |

**Conceito:** *smart cast*. Ao testar `token == null` no primeiro ramo do `when`, o compilador já sabe que nos ramos seguintes o token não é nulo — e `token.length` fica seguro sem nenhum operador de força.

### Exercício 04 — Motor de descontos dinâmicos

O checkout precisa suportar novas promoções **sem que o código do cálculo seja alterado** a cada campanha.

1. Crie `aplicarDesconto`, que recebe o valor original e devolve o preço final.
2. A regra de desconto é definida por **quem chama**, no momento da chamada. Nenhuma porcentagem pode aparecer dentro de `aplicarDesconto`.
3. Criar uma promoção nova não pode exigir nenhuma alteração em `aplicarDesconto`.
4. Demonstre com os cenários abaixo **e mais um criado por você**.

| Cenário (valor original R$ 200,00) | Desconto | Saída esperada |
|------------------------------------|----------|----------------|
| Pagamento via PIX | 5% | R$ 190,00 |
| Cupom promocional | 10% | R$ 180,00 |
| Sem desconto | 0% | R$ 200,00 |

**Conceito:** higher-order function. O tipo `(Double) -> Double` significa "uma função que recebe um Double e devolve um Double" — o parâmetro deixa de ser um dado e passa a ser **código executável**. É o padrão de projeto *Strategy*, que em Java exigiria uma interface e uma classe por campanha.

### Exercício 05 — Filtro de folha de pagamento líquida

O RH quer saber quem permanece acima de um patamar salarial após o desconto previdenciário.

1. Parta de uma lista de salários brutos.
2. Desconte 11% de previdência de cada salário.
3. Mantenha apenas os líquidos **acima de R$ 2.000,00**.
4. Resolva **sem laços** (`for`, `while`) e **sem coleções mutáveis**, em uma única expressão.
5. A lista original deve permanecer inalterada — **comprove imprimindo-a**.

| Entrada | Saída esperada |
|---------|----------------|
| `[1500.0, 2000.0, 2500.0, 3000.0, 5000.0]` | `[2225.00, 2670.00, 4450.00]` |

**Conceito:** `map` e `filter` não alteram a lista de origem — cada um devolve uma lista nova. Por isso o requisito 5 se resolve sozinho, sem esforço extra.

### Exercício 07 — Registro de cashback

Cada transação aprovada gera um novo registro com bônus, mas o histórico original **nunca pode ser alterado**, por auditoria.

1. Modele `Transacao`, com identificador, descrição e valor — todas as propriedades somente leitura.
2. Crie `aplicarCashback`, que devolve um **novo** registro aproveitando os demais dados do original.
3. O novo registro recebe o valor original acrescido de 2%.
4. Imprima o original e o novo, comprovando que o primeiro não mudou.
5. Dois registros de mesmo conteúdo devem ser **iguais**, e a impressão do objeto deve exibir seus valores.

| Entrada | Saída esperada |
|---------|----------------|
| `Transacao(1, "Compra supermercado", 100.0)` | registro original com 100,00 e novo com 102,00 |

**Conceito:** o requisito 5 é a definição de `data class` — `equals()` compara conteúdo e `toString()` exibe os valores. O requisito 2 é o `copy()`.

### Exercício 08 — Regras de reserva de hotel

O status de uma reserva não pode ser alterado livremente pelo resto do sistema.

1. Crie a classe `Reserva` com quantidade de hóspedes, dias de estadia e status. Toda reserva nasce `"PENDENTE"`.
2. O status **não pode ser alterado de fora** da classe: a única forma é o método `confirmar(): Boolean`.
3. `confirmar()` só muda para `"CONFIRMADA"` se hóspedes **e** dias forem maiores que 0.
4. Se a validação falhar, o status permanece e o método retorna `false`.
5. Deixe **comentada** uma linha que tenta atribuir o status diretamente, mostrando que ela não compila.

| Hóspedes | Dias | Retorno | Status final |
|----------|------|---------|--------------|
| 2 | 3 | `true` | CONFIRMADA |
| 0 | 3 | `false` | PENDENTE |
| 2 | 0 | `false` | PENDENTE |

**Conceito:** encapsulamento com `private set` — qualquer um lê o status, só a própria classe escreve nele.

### Exercício 09 — Tarifador de locação de veículos

A locadora aluga carros e caminhões; o caminhão cobra adicional proporcional à carga.

1. Modele `Veiculo` com placa e taxa diária, e `calcularAluguel(dias: Int): Double`.
2. Modele `Carro` e `Caminhao` a partir de `Veiculo`. O caminhão tem tonelagem e taxa por peso, e cobra de forma diferente.
3. Monte **uma única lista** com carros e caminhões e calcule o aluguel de 5 dias de cada item.
4. Ao percorrer a lista, **não é permitido verificar o tipo** de cada objeto nem usar desvios condicionais.

| Tipo | Fórmula |
|------|---------|
| Carro | Dias × Taxa Diária |
| Caminhão | (Dias × Taxa Diária) + (Tonelagem × Taxa por Peso) |

| Veículo (período de 5 dias) | Saída esperada |
|-----------------------------|----------------|
| Carro — diária R$ 120,00 | R$ 600,00 |
| Caminhão — diária R$ 300,00; 8 t; R$ 50,00/t | R$ 1.900,00 |

**Conceito:** o requisito 4 é o próprio polimorfismo. Cada objeto já sabe a sua fórmula, então a chamada executa a versão correta sozinha — sem `if`, sem `is`.

A folha precisa tratar perfis de contratação diferentes sob um mesmo contrato de cálculo.

## 🧯 Problemas comuns

| Sintoma | Causa e solução |
|---------|-----------------|
| "Rodei e só aparece `Hello Android!`" | Está correto — a saída vai para o Logcat, filtrada por `System.out`. |
| Logcat vazio ou cheio de mensagens do sistema | Confirme o filtro `System.out` e que o dispositivo selecionado é o mesmo em que o app roda. Reinicie com ▶ para ver desde o começo. |
| "Gradle sync failed" ou erro de versão de Java | Em **Settings → Build, Execution, Deployment → Build Tools → Gradle**, defina o *Gradle JDK* como o **jbr** que acompanha o Android Studio. |
| "SDK location not found" | O `local.properties` é específico da sua máquina e não vai para o repositório. O Studio o recria ao abrir; se não recriar, instale o SDK em **Tools → SDK Manager**. |
| O emulador não abre | Crie um dispositivo em **Tools → Device Manager** com API 24 ou superior, ou use um celular por USB com Depuração USB ativada. |
