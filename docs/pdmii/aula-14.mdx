## 📖 Conceito

Recompor é o Compose re-executar as funções que **leem** um estado que mudou — e só essas. Cada região da demo conta quantas vezes ela mesma recompôs.

Você não redesenha a tela na mão. Muda o estado, e o Compose recompõe só o pedaço que depende dele. Saber qual pedaço recompõe é o que separa uma tela fluida de uma que reprocessa tudo à toa.

:::caution Armadilha
Recomposição é **escopada**. Toque no botão da região A e veja o contador de recomposições de A subir enquanto o de B fica parado — porque só A lê o estado que mudou. Se todo o estado morasse num lugar só, lido por todos, tudo recomporia junto.
:::

## 💻 Código de Referência

```kotlin title="ui/lessons/L14Recomposition.kt"
@Composable
private fun Regiao(nome: String) {
    var valor by remember { mutableStateOf(0) }
    // Contador de recomposições: um holder comum (não é State), então escrever nele
    // não dispara nova recomposição — ele só registra quantas já aconteceram.
    val recomposicoes = remember { intArrayOf(-1) }
    recomposicoes[0]++

    Card(modifier = Modifier.fillMaxWidth()) {
        Column(
            modifier = Modifier
                .fillMaxWidth()
                .padding(16.dp),
            horizontalAlignment = Alignment.CenterHorizontally,
            verticalArrangement = Arrangement.spacedBy(4.dp)
        ) {
            Text(text = nome, style = MaterialTheme.typography.titleMedium)
            Text(text = "valor: $valor")
            Text(text = "recompôs ${recomposicoes[0]}x")
            Button(onClick = { valor++ }) { Text("mudar valor") }
        }
    }
}
```

## 🧪 Experimente

- Abra o app e vá em **Estado → Recomposição**.
- Toque em "mudar valor" na **Região A** e observe o contador "recompôs Nx" dela subir.
- Repare que o contador da **Região B** fica parado — ela não lê o estado que mudou, então não recompõe.
