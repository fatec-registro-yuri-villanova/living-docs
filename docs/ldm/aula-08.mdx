# Aula 08: Lógica de Submissão de Quiz (Endpoint de validação de respostas)

:::info 🔀 Branch da Aula
Esta aula refere-se à branch: **`aula-08`** — `git checkout aula-08`
:::

Nesta aula, concluímos o módulo do Server da nossa API. Construiremos a lógica principal da aplicação de gamificação, validando os "Streaks" (Ofensivas Diárias) cada vez que as lições são completadas. O mais importante foi garantir a modelagem KMP em que os Clientes e Server possam usar o mesmo payload via DTOs em `[commonMain]`.

## 📖 DTOs Modelados em `ProgressDTOs.kt`

Nossa comunicação flui entre o app e servidor padronizada, ex:

```kotlin
@Serializable
data class SubmitAnswerRequest(
    @SerialName("userId") val userId: Int,
    @SerialName("questionId") val questionId: Int,
    @SerialName("selectedOption") val selectedOption: Int
)

@Serializable
data class SubmitAnswerResponse(
    @SerialName("isCorrect") val isCorrect: Boolean,
    @SerialName("correctAnswer") val correctAnswer: Int?,
    val message: String,
    val newStreak: Int? = null,
    val streakFreezes: Int? = null
)
```

## 💻 Código de Referência (O Serviço)

A injeção ocorre direto nas rotas de progress (`ProgressRoutes.kt`) garantindo flexibilidade usando Supabase Ktor.

```kotlin title="server/.../routes/ProgressRoutes.kt"
fun Route.progressRoutes(supabase: SupabaseClient) {
    route("/progress") {
        post("/submit") {
            try {
                val request = call.receive<SubmitAnswerRequest>()
                // ... lógica de verificação
                call.respond(SubmitAnswerResponse(...))
            } catch (e: Exception) {
               // Erro interno
            }
        }
    }
}
```

O principal fator arquitetural para a matriz do _streak_ temporal é gerenciar o **Timezone** reportado e os pulos de congelamento (_Freezes_). Ele avalia o rolamento das datas de hoje:

```kotlin
val zoneId = try { ZoneId.of(timezoneId) } catch (e: Exception) { ZoneId.of("UTC") }
val today = ZonedDateTime.now(zoneId).toLocalDate()
```
