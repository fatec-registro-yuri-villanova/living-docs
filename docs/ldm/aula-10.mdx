# Aula 10: Scripts de Semente (Seeding) e Admin

Nesta aula, aprendemos a migrar o nosso massivo bloco de **Seeding** (A injeção dos dados base da aplicação) de um comportamento acoplado ao ciclo de vida do servidor (na inicialização) para um Endpoint Administrativo **restrito e altamente performático** usando a estratégia de envio por arrays no Supabase KMP com natividade de Upsert.

Ao final, sua API estará estruturalmente madura para lidar com o preenchimento de massas de teste (Seeds) em lote na nuvem e o projeto manterá as Controller e Services separadas graças à Arquitetura Limpa.

---

## 🏗 Estrutura da Funcionalidade

A injeção de seeds consistia originalmente em loops iterativos demorados no servidor legado onde validávamos 1 por 1. No MergeSkills KMP, reestruturamos a Rota separando responsabilidades: A Rota ficou apenas e exclusivamente em `/routes/AdminRoutes.kt` enquanto todo o trabalho de banco foi isolado dentro do `/services/SeedService.kt`.

### DTOs em Módulo Compartilhado

Na pasta do módulo **`shared`**, precisamos garantir os objetos responsáveis pelo parsing dos inserts de Seed. Exemplo da payload genérica de uma lição (QuestionInsert):

```kotlin
// com/fatec/merge_skills_kmp/domain/models/Question.kt
@Serializable
data class QuestionInsert(
    @SerialName("lesson_id")
    val lessonId: Int,
    val question: String,
    val code: String? = null,
    val options: List<String>,
    @SerialName("correct_answer")
    val correctAnswer: Int,
    val order: Int
)
```

> **📌 Diferencial de Otimização (Batch Upsert):** No legado, eram efetuadas dezenas conexões e validações individuais no Supabase (`client.from("questions").insert(q)`). No MergeSkills KMP mudamos a arquitetura para envio em massa usando a função **Upsert**: `client.from("questions").upsert(questions)`. Isso permite lidar com recálculo de forma automática e otimiza o overhead drasticamente de centenas para apenas 1-2 hits de API.

## 🛠 O Serviço: SeedService

Para obediência ao Clean Code (Clean Architecture), isolamos *Apenas O Que Interessa Ao DB*. Nosso Service cuida de gerir as instâncias dos nossos 4 Cursos (`Java Icaro, Kotlin, Python, TypeScript`) sem poluir a Web Controller. 

```kotlin
// com/fatec/merge_skills_kmp/services/SeedService.kt
class SeedService(private val client: SupabaseClient) {

    suspend fun executeSeed(): Int {
        var newCoursesInserted = 0
        // ... Preparação dos Upserts com Listas de Cursos ...

        if (coursesToUpsert.isNotEmpty()) {
            val insertedCourses = client.from("courses").upsert(coursesToUpsert) { select() }.decodeList<Course>()
        }
        
        // Dispara Inclusão Completa para Relacionamentos
        return insertedCourses.size
    }
}
```

## 🌐 O Endpoint Administrativo (AdminRoutes)

Localizado em `com.fatec.merge_skills_kmp.routes.AdminRoutes.kt`, esta view invoca nosso SeedService garantindo que só devolva HTTPs OK / Conflict. Não carrega Array de Listas!

```kotlin
// com/fatec/merge_skills_kmp/routes/AdminRoutes.kt
fun Route.adminRoutes(client: SupabaseClient) {
    route("/admin") {
        post("/seed") {
            try {
                val seedService = SeedService(client)
                val newCoursesInserted = seedService.executeSeed()

                call.respond(
                    HttpStatusCode.OK, 
                    SeedResponse(message = "Database seeded successfully", new_courses_inserted = newCoursesInserted)
                )
            } catch (e: Exception) {
                call.respond(HttpStatusCode.InternalServerError, SeedErrorResponse(error = "Failed to seed database: ${e.message}"))
            }
        }
    }
}
```

### O Disparo do Gatilho

As rotas são injetadas em `Application.configureRouting()`, através do registro na `Routing.kt`:

```kotlin
progressRoutes(supabase)
uploadRoutes(supabase)
adminRoutes(supabase) // <--- O Módulo Seed Admin
```

⚠️ Pelo fato da rota ser aberta e executar massas imensas, em um ambiente em Produção (Module `Auth`) será estritamente necessário proteger as rotas do prefixo `/admin` checando as Policies da Role ou JWT Claims (Somente `admin`) a fim de impedir ataques DoS.

## 🧪 Abordagem Híbrida: Idempotência Polimórfica com Constraints

Como o plugin nativo (PostgREST) falha quando um _JSON Batch_ possui chaves com propriedades nulas num Array, implementamos no `SeedService.kt` uma injeção de segurança de mapeamento JSON:

```kotlin
private suspend fun upsertQuestionsPolymorphic(questions: List<QuestionInsert>) {
    val qWithCode = questions.filter { it.code != null }
    val qWithoutCode = questions.filter { it.code == null }
        
    // Divide e Conquista: Os objetos exatos vão perfeitamente em Batch!
    if (qWithCode.isNotEmpty()) client.from("questions").upsert(qWithCode)
    if (qWithoutCode.isNotEmpty()) client.from("questions").upsert(qWithoutCode)
}
```

Levante o Servidor (`./gradlew run`) e invoque o novo Endpoint Otimizado via POST:
```sh
curl -X POST http://localhost:8080/admin/seed
```
