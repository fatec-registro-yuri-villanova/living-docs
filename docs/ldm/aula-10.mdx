# Aula 10: Scripts de Semente (Seeding) e Admin

Nesta aula, aprendemos a implementar o nosso bloco de **Seeding** (A injeção dos dados base da aplicação) como um Endpoint Administrativo **restrito e altamente performático** usando a estratégia de envio por arrays no Supabase KMP com a função nativa de Upsert.

Ao final, sua API estará estruturalmente madura para lidar com o preenchimento de massas de teste (Seeds) em lote na nuvem, e o projeto manterá as Controller e Services separadas graças à Arquitetura Limpa.

---

## 🏗 Estrutura da Funcionalidade

Para preencher nossa base com velocidade sem afetar a inicialização do Ktor, estruturamos uma Rota que separa as responsabilidades com elegância: A exposição da API fica exclusivamentre em `/routes/AdminRoutes.kt` enquanto toda a complexidade e motor de banco fica isolada dentro de `/services/SeedService.kt`.

### DTOs em Módulo Compartilhado

Na pasta do módulo **`shared`**, precisamos garantir os objetos responsáveis pelo parsing dos inserts de Seed. Exemplo da payload genérica de uma lição (QuestionInsert):

```kotlin
// com/fatec/merge_skills_kmp/domain/models/Question.kt
@Serializable
data class QuestionInsert(
    @SerialName("lesson_id")
    val lessonId: Int,
    val question: String,
    val code: String? = null,
    val options: List<String>,
    @SerialName("correct_answer")
    val correctAnswer: Int,
    val order: Int
)
```

> **📌 Otimização com Batch Upsert:** Em vez de iterarmos e dispararmos dezenas de conexões individuais para cada registro, nós implementamos a arquitetura de envio em massa via **Upsert**: `client.from("questions").upsert(questions)`. Essa estratégia permite criar ou sobrescrever os registros automaticamente, otimizando o overhead de rede para enviar centenas de questões em apenas 1-2 hits de API.

## 🛠 O Serviço: SeedService

Para obediência ao Clean Code (Clean Architecture), isolamos *Apenas O Que Interessa Ao DB*. Nosso Service cuida de injetar e verificar a ordem de dependências dos nossos 4 Cursos Base (`Java Icaro, Kotlin, Python, TypeScript`) sem poluir a Controller que atende na Web.

## 🌐 O Endpoint Administrativo (AdminRoutes)

Localizado em `com.fatec.merge_skills_kmp.routes.AdminRoutes.kt`, esta view invoca nosso SeedService garantindo que só devolva HTTPs OK / Conflitos Tratados. Ela lida apenas com a requisição e a resposta!

```kotlin
// com/fatec/merge_skills_kmp/routes/AdminRoutes.kt
fun Route.adminRoutes(client: SupabaseClient) {
    route("/admin") {
        post("/seed") {
            try {
                val seedService = SeedService(client)
                val newCoursesInserted = seedService.executeSeed()

                call.respond(
                    HttpStatusCode.OK, 
                    SeedResponse(message = "Database seeded successfully", new_courses_inserted = newCoursesInserted)
                )
            } catch (e: Exception) {
                call.respond(HttpStatusCode.InternalServerError, SeedErrorResponse(error = "Failed to seed database: ${e.message}"))
            }
        }
    }
}
```

### O Disparo do Gatilho

As rotas são injetadas em `Application.configureRouting()`, através do registro na `Routing.kt`:

```kotlin
progressRoutes(supabase)
uploadRoutes(supabase)
adminRoutes(supabase) // <--- O Módulo Seed Admin
```

⚠️ Como a rota executa escrituras em massa, em um ambiente de Produção real (Módulo de Auth) seria estritamente necessário proteger as rotas do prefixo `/admin` checando as Policies da Role ou JWT Claims (Somente role `admin` logado) para impedir ataques DoS.

## 🧪 Abordagem Resiliente: Lidando com Constraints via `upsertQuestionsPolymorphic`

Quando realizamos um Upsert em lote (um ArrayList transformado em requisição JSON) no Supabase, o motor por trás dele chamado `PostgREST` **exige estritamente que todos os objetos do lote possuam as exatamente as mesmas chaves**. 

Se submetermos um lote onde a Questão A tem a propriedade `"code": "print(1)"` declarada, e a Questão B ignora isso porque o `code` é inferido nulo (omitido ou serializado diferente), a API retornará o erro 400: *"All object keys must match"*.

Para manter essa restrição performática sem poluir nosso código, implementamos o utilitário polimórfico no `SeedService.kt`:

```kotlin
private suspend fun upsertQuestionsPolymorphic(questions: List<QuestionInsert>) {
    // Filtramos garantindo lotes homogêneos
    val qWithCode = questions.filter { it.code != null }
    val qWithoutCode = questions.filter { it.code == null }
        
    // Divide e Conquista: Os objetos simétricos são roteados como blocos independentes.
    if (qWithCode.isNotEmpty()) client.from("questions").upsert(qWithCode)
    if (qWithoutCode.isNotEmpty()) client.from("questions").upsert(qWithoutCode)
}
```

Levante o Servidor (`./gradlew run`) e invoque nosso novo Endpoint de Massa via POST:

```sh
curl -X POST http://localhost:8080/admin/seed
```
