# Aula 10: Scripts de Semente (Seeding) e Admin

Nesta aula, aprendemos a migrar o nosso massivo bloco de **Seeding** (A injeção dos dados base da aplicação) de um comportamento acoplado ao ciclo de vida do servidor (na inicialização) para um Endpoint Administrativo **restrito e muito mais performático** usando a estratégia de envio por arrays no Supabase KMP. 

Ao final, sua API estará estruturalmente madura para lidar com massa de dados de teste (Seeds).

---

## 🏗 Estrutura da Funcionalidade

A injeção de seeds consistia originalmente em loops iterativos demorados no servidor legado. Para o MergeSkills KMP, reestruturamos a Rota em `/routes/AdminRoutes.kt` e atualizamos nossos DTOs.

### DTOs do Seed

Na pasta do módulo **`shared`**, precisamos garantir os objetos responsáveis pelo parsing dos inserts de Seed. O destaque da Aula é a inclusão da Payload completa das lições:

```kotlin
// com/fatec/merge_skills_kmp/domain/models/Question.kt
@Serializable
data class QuestionInsert(
    @SerialName("lesson_id")
    val lessonId: Int,
    val question: String,
    val code: String? = null,
    val options: List<String>,
    @SerialName("correct_answer")
    val correctAnswer: Int,
    val order: Int
)
```

> **📌 Diferencial de Otimização (Batch Insert):** No legado, eram efetuadas 84 conexões de inserção individuais no Supabase (`client.from("questions").insert(q)`), uma por pergunta. No MergeSkills KMP as inserimos em uma tacada só passando uma Tabela Inteira com Arrays `client.from("questions").insert(questions)` melhorando drásticamente o overhead da requisição.

## 🛠 O Endpoint de Seeding (AdminRoutes)

Localizado em `com.fatec.merge_skills_kmp.routes.AdminRoutes.kt`, esta classe encapsulará toda a manipulação do painel administrativo, inicialmente apenas para povoar o DB.

```kotlin
fun Route.adminRoutes(client: SupabaseClient) {
    route("/admin") {
        post("/seed") {
            try {
                seedUser(client)
                // ...
                val existingCourses = client.from("courses").select().decodeList<Course>()
                // ...
                val coursesToInsert = listOf(
                    CourseInsert("Java Icaro", ...),
                    // ...
                )
```

Nós resgatados exatamente os mesmos 4 cursos base da API original: **Java, Kotlin, Python, TypeScript**. 

### O Disparo do Gatilho

As rotas são injetadas em `Application.configureRouting()`, através do registro na `Routing.kt`:

```kotlin
progressRoutes(supabase)
uploadRoutes(supabase)
adminRoutes(supabase) // <--- O Módulo Seed Admin
```

⚠️  Pelo fato da rota ser aberta e executar massas imensas, em um ambiente em Produção (Module `Auth`) será estritamente necessário proteger as rotas do prefixo `/admin` checando as Policies da Role (Somente `admin` na tabela Role logando) a fim de impedir ataques DoS de gravação.

## 🧪 Estratégia de Idempotência e Recuperação Parcial

Uma das grandes melhorias dessa migração é a capacidade de **Idempotência**. O Seeding não é destrutivo. Ele varre as coleções e insere apenas os filhos que estão faltando. Se o servidor cair no meio do fluxo e o banco de dados ficar com cursos mas sem questões, ao executar novamente o endpoint, ele "costurará" exatamente aquilo que faltava sem duplicar informações no seu Supabase.

Levante o Servidor (`./gradlew run`) e invoque o novo Endpoint via POST:

Via cURL no terminal (Windows/Linux):
```sh
curl -X POST http://localhost:8080/admin/seed
```

### ✅ Retorno de Sucesso Otimizado:

```json
{
  "message": "Database seeded successfully",
  "new_courses_inserted": 4
}
```

Caso você envie o request novamente (logo após os cursos já terem sido injetados), o servidor varrerá em List Comprehensions a verificação de registros órfãos pulando blocos inúteis:

```json
{
  "message": "Database seeded successfully",
  "new_courses_inserted": 0
}
```

*(Zero novos cursos)* Com isso, toda a nossa equipe de Frontend Web/Mobile estará com sua base local perfeitamente recheada, e tolerante à falhas de network, com nossos mesmos +80 exercícios básicos de validação, para todos testarem o MergeSkills de forma integrada! 🚀
