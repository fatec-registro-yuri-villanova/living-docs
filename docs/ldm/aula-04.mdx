# Aula 04: O documento da etiqueta

:::info 🔀 Código da Aula
- **Ponto de partida:** o estado ao fim da aula anterior
- **Gabarito final:** `git checkout main`
:::

## 📖 Conceito

Até aqui, cada aula produziu uma peça isolada: `Impressora` e `QuebraDeLinha` sabem de colunas e dots; `Pc860` sabe converter texto para os bytes que a LT-8359 entende. Nenhuma delas sabe o que é uma etiqueta. Esta aula fecha essa lacuna com `LabelDocument` — o modelo que descreve *o que* vai ser impresso, sem dizer *como*.

`LabelDocument` é o contrato entre as quatro partes do app que ainda vão ser construídas nas próximas aulas: a UI produz um `LabelDocument`, o preview desenha um `LabelDocument`, o renderizador ESC/POS transforma um `LabelDocument` em bytes, e o banco guarda um `LabelDocument`. É por isso que este arquivo não importa Compose nem nada específico de plataforma — se importasse, arrastaria essa dependência para os outros três consumidores, mesmo os que não têm nada a ver com tela.

### Por que `sealed interface`

`Bloco` é um `sealed interface`. Isso diz ao compilador Kotlin que a lista de tipos que podem implementar `Bloco` é fechada e conhecida em tempo de compilação — só os subtipos declarados no mesmo arquivo existem, ponto. A consequência aparece do lado de quem *consome* um `Bloco`: um `when (bloco)` que trata todos os subtipos não precisa de um ramo `else`, porque o compilador já sabe que não falta nenhum caso. E se alguém, um dia, acrescentar um subtipo novo a `Bloco` e esquecer de tratá-lo num desses `when`, o projeto para de compilar naquele ponto — o esquecimento vira um erro na hora de compilar, não um bug para descobrir em produção. Essa rede de proteção é para o renderizador da aula 05.

### Por que `normalizado()`

`Bloco.Titulo` é açúcar sintático: semanticamente ele é só uma `Linha` em escala 2, centralizada. Em vez de fazer cada consumidor de `Bloco` (o renderizador, o preview) saber tratar `Titulo` como um caso especial, `normalizado()` converte `Titulo` em `Linha` uma única vez, antes de qualquer um deles rodar. Isso deixa o renderizador e o preview com um caso a menos para se preocupar.

E tem um detalhe que só o hardware ensina: repare que `Titulo` normalizado *não* vira negrito. Isso é proposital. A LT-8359 imprime ênfase (negrito) como um duplo impacto da cabeça de impressão, deslocado horizontalmente por uma fração de dot. Em escala normal esse deslocamento cria o efeito de negrito esperado. Mas em escala 2x — que é exatamente a escala que `normalizado()` usa para títulos — o segundo impacto cai *dentro* do próprio glifo, já alargado, em vez de ao lado dele. O resultado não é um título em negrito: é um título borrado.

```kotlin title="shared/src/commonTest/kotlin/com/fatec/printec/etiqueta/EtiquetaDeTesteTest.kt"
package com.fatec.printec.etiqueta

import kotlin.test.Test
import kotlin.test.assertEquals
import kotlin.test.assertTrue

class EtiquetaDeTesteTest {

    @Test
    fun `a regua tem exatamente 32 caracteres`() {
        val regua = etiquetaDeCalibracao().blocos
            .filterIsInstance<Bloco.Linha>()
            .first { it.texto.length >= 32 }
        assertEquals(32, regua.texto.length)
        assertEquals(1, regua.escala)
    }

    @Test
    fun `a calibracao exercita acentos do portugues`() {
        val textos = etiquetaDeCalibracao().blocos
            .filterIsInstance<Bloco.Linha>().map { it.texto }
        assertTrue(textos.any { it.contains("ação") })
    }

    @Test
    fun `a calibracao inclui um QR de referencia`() {
        assertTrue(etiquetaDeCalibracao().blocos.any { it is Bloco.Qr })
    }

    @Test
    fun `a calibracao cobre as oito escalas, de 1x a 8x`() {
        // Spec §8: 1x a 8x. Cobertura reduzida aqui custa uma sessao de testes
        // de hardware inteira -- este e o instrumento que responde perguntas
        // em aberto sobre a LT-8359.
        val escalas = etiquetaDeCalibracao().blocos
            .filterIsInstance<Bloco.Linha>()
            .filter { it.texto.startsWith("escala ") }
            .map { it.escala }
        assertEquals((1..8).toList(), escalas)
    }

    @Test
    fun `nenhum caractere da calibracao e substituido`() {
        val doc = etiquetaDeCalibracao()
        val fora = doc.blocos.filterIsInstance<Bloco.Linha>()
            .sumOf { Pc860.codificar(it.texto).substituidos }
        assertEquals(0, fora)
    }
}
```

## Passo 1 — LabelDocument

```kotlin title="shared/src/commonMain/kotlin/com/fatec/printec/etiqueta/LabelDocument.kt"
package com.fatec.printec.etiqueta

enum class Alinhamento { ESQUERDA, CENTRO, DIREITA }

sealed interface Bloco {
    /** Açúcar para Linha(escala = 2, CENTRO). Ver [normalizado] quanto ao negrito. */
    data class Titulo(val texto: String) : Bloco

    data class Linha(
        val texto: String,
        val escala: Int = 1,
        val alinhamento: Alinhamento = Alinhamento.ESQUERDA,
        val negrito: Boolean = false,
    ) : Bloco

    data class Qr(val conteudo: String, val tamanhoModulo: Int = 6) : Bloco

    data class Avanco(val milimetros: Int) : Bloco
}

data class LabelDocument(
    val blocos: List<Bloco> = emptyList(),
    val copias: Int = 1,
)

/**
 * Normaliza Titulo para Linha, para que renderizador e preview tratem um caso a menos.
 *
 * Sem negrito de proposito. A LT-8359 imprime enfase como duplo impacto
 * deslocado na horizontal; em largura 2x esse segundo impacto cai dentro do
 * proprio glifo, preenche o vao entre as colunas de dots e o titulo sai
 * borrado. Na etiqueta de calibracao isso aparece lado a lado: "CALIBRACAO"
 * (2x + negrito) ilegivel logo acima de "escala 2x" (2x puro) nitido.
 */
fun Bloco.normalizado(): Bloco = when (this) {
    is Bloco.Titulo -> Bloco.Linha(
        texto = texto,
        escala = 2,
        alinhamento = Alinhamento.CENTRO,
    )
    else -> this
}
```

Quatro blocos, quatro necessidades diferentes de uma etiqueta: `Titulo` para o cabeçalho, `Linha` para texto comum (com escala, alinhamento e negrito próprios), `Qr` para o código de barras 2D, e `Avanco` para empurrar o papel um número de milímetros sem imprimir nada — útil para dar espaço entre seções da etiqueta. `LabelDocument` é só a lista ordenada desses blocos mais `copias`, o número de vezes que a etiqueta deve sair da impressora.

## Passo 2 — A etiqueta de calibração

```kotlin title="shared/src/commonMain/kotlin/com/fatec/printec/etiqueta/EtiquetaDeTeste.kt"
package com.fatec.printec.etiqueta

/**
 * Etiqueta de diagnostico. Confirma em papel o que o autoteste da impressora
 * so deixou inferir: se a regua de 32 colunas ocupa a largura inteira sem
 * quebrar, os 384 dots estao certos.
 *
 * E tambem a primeira ferramenta quando algo parece errado: se ela imprime, o
 * problema esta no conteudo, nao na conexao.
 */
fun etiquetaDeCalibracao(): LabelDocument = LabelDocument(
    blocos = listOf(
        Bloco.Titulo("CALIBRACAO"),
        Bloco.Linha("12345678901234567890123456789012"),   // 32 colunas exatas
        // Spec §8 pede 1x a 8x: e este instrumento que vai responder as
        // perguntas de hardware em aberto sobre a LT-8359, e cobertura
        // reduzida aqui custa uma sessao de testes inteira.
        Bloco.Linha("escala 1x"),
        Bloco.Linha("escala 2x", escala = 2),
        Bloco.Linha("escala 3x", escala = 3),
        Bloco.Linha("escala 4x", escala = 4),
        Bloco.Linha("escala 5x", escala = 5),
        Bloco.Linha("escala 6x", escala = 6),
        Bloco.Linha("escala 7x", escala = 7),
        Bloco.Linha("escala 8x", escala = 8),
        Bloco.Linha("ação não coração Ângela"),
        Bloco.Linha("direita", alinhamento = Alinhamento.DIREITA),
        Bloco.Linha("centro", alinhamento = Alinhamento.CENTRO),
        Bloco.Qr("PRINTEC-CALIBRACAO"),
    ),
    copias = 1,
)
```

A régua de `"12345678901234567890123456789012"` tem exatamente 32 caracteres. Até aqui, `Impressora.DOTS_LARGURA = 384` e as 32 colunas que vêm dele (aula 02) são inferência a partir do datasheet da Font A — nunca foram confirmadas em papel. Esta etiqueta é a ferramenta que faz essa confirmação: se a régua sai inteira, numa linha só, sem quebrar, os 384 dots estão certos. A aula 15 é onde essa etiqueta é finalmente impressa de verdade na LT-8359.

Ela também é a primeira ferramenta de diagnóstico do projeto, antes mesmo de existir uma UI para escolher o que imprimir: se a etiqueta de calibração imprime — corretamente, sem lixo nos acentos, com o QR legível — o problema em qualquer relato de "não imprime direito" está no conteúdo daquela etiqueta específica, não na conexão com a impressora nem no transporte (aulas 06 a 08).

Repare que a etiqueta cobre as oito escalas de 1x a 8x (spec §8) e uma frase com acentuação do português (`"ação não coração Ângela"`) — a mesma classe de caractere que `Pc860` (aula 03) precisa converter sem substituição.

Rode o teste de novo:

```bash
./gradlew :shared:jvmTest --tests "com.fatec.printec.etiqueta.EtiquetaDeTesteTest"
```

## ⚠️ Atenção

`normalizado()` converte `Titulo` para `Linha` — mas o que acontece se, por algum caminho, um `Titulo` *não normalizado* chegar até o renderizador da aula 05? O `when` que vai varrer os blocos ali não vai ter um ramo `else` (é exatamente a rede de proteção do sealed interface que a seção de Conceito descreveu), então o ramo `is Bloco.Titulo` dele precisa existir — e nesse ramo não há conversão nenhuma, só uma chamada a `error(...)`, que derruba a execução com uma exceção. Isso é proposital: se um dia alguém chamar o renderizador direto, sem passar pelos blocos por `normalizado()` primeiro, o app falha alto e visível, na hora, em vez de imprimir um título errado (sem a escala e o centro que o normalizado() daria) e ninguém perceber até reclamação do usuário.

### Acrescente um subtipo a `Bloco`

Em `LabelDocument.kt`, dentro do `sealed interface Bloco`, acrescente `data class CodigoDeBarras(val conteudo: String) : Bloco`.

Rode:

```bash
./gradlew :shared:compileKotlinJvm
```

Anote o resultado. Ele te surpreende? Nada neste projeto, hoje, quebra — o compilador aceita `CodigoDeBarras` de primeira, sem reclamar de nenhum `when` incompleto.

Volte a `normalizado()` e leia o `when` com atenção: ele tem um ramo `is Bloco.Titulo` e um `else -> this`. `else` cobre qualquer caso não citado explicitamente — inclusive um subtipo que nem existia quando esse `when` foi escrito. É por isso que adicionar `CodigoDeBarras` não quebrou nada: neste ponto do projeto, `normalizado()` é o único lugar que faz `when` sobre `Bloco`, e ele tem uma saída de escape.

A rede de proteção que a seção de Conceito descreveu só vai aparecer na **aula 05**, no `when` do renderizador — lá não existe `else`: cada `is Bloco.X` precisa estar escrito à mão, e um subtipo esquecido vira erro de compilação, não um bug silencioso em produção. Você acabou de ver o outro lado dessa moeda: um `when` com `else` não te avisa de nada.

Desfaça a alteração (remova `CodigoDeBarras`) antes de seguir para o exercício 2.
