# Aula 11: CMS Desktop — Setup e Auth

:::info 🔀 Branches da Aula

## 📖 Contexto

O **CMS (Content Management System)** é uma aplicação Desktop construída com **Compose for Desktop** que permite gerenciar cursos, aulas e quizzes do MergeSkills. Roda na JVM e reutiliza os modelos do módulo `shared/`.

Nesta aula construímos a **infraestrutura base** do CMS:
- Janela principal maximizada
- Roteamento simples entre `LoginScreen` e `CmsScreen` via `mutableStateOf`
- Autenticação com verificação de `role = "admin"`
- Persistência de sessão com `multiplatform-settings`
- Injeção de dependência com **Koin**

```kotlin title="composeApp/build.gradle.kts"
        // highlight-end
    }

```

E em `gradle/libs.versions.toml`:

```toml title="gradle/libs.versions.toml"
[versions]
multiplatform-settings = "1.1.1"

[libraries]
multiplatform-settings = { module = "com.russhwolf:multiplatform-settings", version.ref = "multiplatform-settings" }
```

:::tip Por que `multiplatform-settings` e não DataStore?
O DataStore (usado no Android) depende de `Context` da plataforma. No Desktop JVM, usamos `multiplatform-settings` com `PreferencesSettings` — que internamente usa o `java.util.prefs.Preferences` da JVM.
:::

## Passo 2 — `KtorUserRepository` (camada de dados)

Implementa a interface `UserRepository` do `shared/` fazendo chamadas HTTP para a API Ktor.

```kotlin title="desktopMain/.../data/KtorUserRepository.kt"
class KtorUserRepository(
    private val client: HttpClient,
    private val baseUrl: String
) : UserRepository {

    override suspend fun login(request: LoginRequest): Result<AuthResponse> = runCatching {
        client.post("$baseUrl/auth/login") {
            contentType(ContentType.Application.Json)
            setBody(request)
        }.body()
    }

    override suspend fun register(request: RegisterRequest): Result<AuthResponse> = runCatching {
        client.post("$baseUrl/auth/register") {
            contentType(ContentType.Application.Json)
            setBody(request)
        }.body()
    }

    override suspend fun getUserProfile(userId: Int): Result<User> = runCatching {
        client.get("$baseUrl/users/$userId").body()
    }

    override suspend fun updateStreak(userId: Int): Result<User> = runCatching {
        client.post("$baseUrl/users/$userId/streak").body()
    }
}
```

:::note `runCatching`
Cada função envolve a chamada em `runCatching {}` que retorna `Result<T>` — se a requisição lançar uma exceção, ela é capturada em `Result.failure`. O `AuthViewModel` trata esse resultado com `.onSuccess` e `.onFailure`.
:::

## Passo 3 — `DesktopModule` (Koin DI)

Define como cada dependência é criada e injetada. O Koin vai montar o grafo automaticamente.

```kotlin title="desktopMain/.../di/DesktopModule.kt"
val desktopAppModule = module {

    // 1. HttpClient com engine CIO (JVM) e suporte a JSON
    single<HttpClient> {
        HttpClient(CIO) {
            install(ContentNegotiation) {
                json(Json { ignoreUnknownKeys = true })
            }
        }
    }

    // 2. Repositório que chama a API local
    single<UserRepository> {
        KtorUserRepository(
            client = get(),
            baseUrl = "http://localhost:8080"
        )
    }

    // 3. Persistência local via java.util.prefs (nó "mergeskills-cms")
    single<Settings> {
        PreferencesSettings(Preferences.userRoot().node("mergeskills-cms"))
    }

    // 4. ViewModel recebe o repositório e as settings via get()
    single {
        AuthViewModel(
            repository = get(),
            settings = get()
        )
    }
}
```

:::info Como o Koin resolve dependências
`get()` dentro de um bloco `single {}` pede ao Koin a instância já registrada daquele tipo. A ordem de declaração não importa — o Koin resolve o grafo de forma lazy.
:::

## Passo 4 — `AuthViewModel`

Gerencia o ciclo completo de autenticação e a persistência de sessão.

### UiState

```kotlin title="desktopMain/.../viewmodel/AuthViewModel.kt"
sealed class AuthUiState {
    object Idle : AuthUiState()       // estado inicial
    object Loading : AuthUiState()    // chamada em andamento
    data class Success(val user: User) : AuthUiState()  // login OK
    data class Error(val message: String) : AuthUiState() // erro de rede
    object NotAdmin : AuthUiState()   // login OK, mas não é admin
}
```

### `login()`

```kotlin
fun login(email: String, password: String) {
    scope.launch {
        _authState.value = AuthUiState.Loading
        repository.login(LoginRequest(email, password))
            .onSuccess { response ->
                val user = response.user
                if (user != null && user.role == "admin") {
                    saveSession(user)                          // persiste na JVM
                    _authState.value = AuthUiState.Success(user)
                } else {
                    _authState.value = AuthUiState.NotAdmin   // não navega!
                }
            }
            .onFailure { error ->
                _authState.value = AuthUiState.Error(error.message ?: "Erro desconhecido")
            }
    }
}
```

### `isLoggedIn()` e persistência de sessão

```kotlin
// Verificação síncrona chamada com runBlocking no main()
suspend fun isLoggedIn(): Boolean {
    val userId = settings.getIntOrNull("user_id")
    return userId != null && userId > 0
}

// Salva dados do usuário nas preferences da JVM
private fun saveSession(user: User) {
    settings.putInt("user_id", user.id)
    settings.putString("user_name", user.name ?: user.username)
    settings.putString("user_role", user.role)
}

// Remove tudo ao fazer logout
private fun clearSession() {
    settings.remove("user_id")
    settings.remove("user_name")
    settings.remove("user_role")
}
```

:::caution Estado `NotAdmin`
Um usuário que existe no banco mas não tem `role = "admin"` recebe `NotAdmin` — **nunca** `Success`. A tela exibe uma mensagem específica sem navegar para o CMS.
:::

## Passo 5 — `LoginScreen`

Composable centralizado. Observa o `authState` e navega automaticamente ao receber `Success`.

```kotlin title="desktopMain/.../features/auth/LoginScreen.kt"
@Composable
fun LoginScreen(
    viewModel: AuthViewModel,
    onLoginSuccess: () -> Unit
) {
    val authState by viewModel.authState.collectAsState()

    // Navegação reativa: só dispara quando o estado muda para Success
    LaunchedEffect(authState) {
        if (authState is AuthViewModel.AuthUiState.Success) {
            onLoginSuccess()
        }
    }

    var email by remember { mutableStateOf("") }
    var password by remember { mutableStateOf("") }

    Box(
        modifier = Modifier.fillMaxSize().background(Color(0xFF0F0F0F)),
        contentAlignment = Alignment.Center
    ) {
        Card(modifier = Modifier.width(400.dp)) {
            Column(
                modifier = Modifier.padding(32.dp),
                verticalArrangement = Arrangement.spacedBy(16.dp)
            ) {
                Text("MergeSkills CMS", style = MaterialTheme.typography.headlineMedium)

                OutlinedTextField(
                    value = email, onValueChange = { email = it },
                    label = { Text("E-mail") }, modifier = Modifier.fillMaxWidth(), singleLine = true
                )
                OutlinedTextField(
                    value = password, onValueChange = { password = it },
                    label = { Text("Senha") },
                    visualTransformation = PasswordVisualTransformation(),
                    modifier = Modifier.fillMaxWidth(), singleLine = true
                )

                // Mensagem de erro de rede
                if (authState is AuthViewModel.AuthUiState.Error) {
                    Text(
                        text = (authState as AuthViewModel.AuthUiState.Error).message,
                        color = MaterialTheme.colorScheme.error,
                        style = MaterialTheme.typography.bodySmall
                    )
                }

                // Mensagem específica para usuário sem role admin
                if (authState is AuthViewModel.AuthUiState.NotAdmin) {
                    Text(
                        text = "Conta sem permissão de admin",
                        color = MaterialTheme.colorScheme.tertiary,
                        style = MaterialTheme.typography.bodySmall
                    )
                }

                Button(
                    onClick = { viewModel.login(email, password) },
                    modifier = Modifier.fillMaxWidth(),
                    enabled = authState !is AuthViewModel.AuthUiState.Loading
                ) { Text("Entrar") }

                if (authState is AuthViewModel.AuthUiState.Loading) {
                    LinearProgressIndicator(modifier = Modifier.fillMaxWidth())
                }
            }
        }
    }
}
```

## Passo 7 — `main.kt` (entry point e roteamento)

Inicializa o Koin, verifica a sessão e decide a tela inicial. A navegação é feita com um simples `mutableStateOf<Screen>` — sem `NavController`.

```kotlin title="desktopMain/.../main.kt"
sealed class Screen {
    object Login : Screen()
    object Cms : Screen()
}

fun main() {
    // Koin inicializado ANTES do application {}
    val koin = startKoin {
        modules(desktopAppModule)
    }.koin

    val authViewModel = koin.get<AuthViewModel>()

    application {
        // runBlocking só é chamado UMA VEZ dentro do remember
        var currentScreen by remember {
            val initial: Screen =
                if (runBlocking { authViewModel.isLoggedIn() }) Screen.Cms else Screen.Login
            mutableStateOf(initial)
        }

        Window(
            onCloseRequest = ::exitApplication,
            title = "MergeSkills CMS",
            state = rememberWindowState(
                placement = WindowPlacement.Maximized,
                width = 1280.dp,
                height = 800.dp
            )
        ) {
            MaterialTheme(colorScheme = darkColorScheme()) {
                when (currentScreen) {
                    Screen.Login -> LoginScreen(
                        viewModel = authViewModel,
                        onLoginSuccess = { currentScreen = Screen.Cms }
                    )
                    Screen.Cms -> CmsScreen(
                        authViewModel = authViewModel,
                        onLogout = { currentScreen = Screen.Login }
                    )
                }
            }
        }
    }
}
```

:::info Por que `startKoin` fora do `application {}`?
O `application {}` do Compose Desktop é um lambda recomposto. Inicializar o Koin dentro dele causaria re-inicialização a cada recomposição. Iniciando fora, o Koin é um singleton da JVM.
:::

## ⚠️ Atenção — `AndroidManifest.xml`

O módulo `composeApp` usa `namespace = "com.fatec.merge_skills_kmp.android"` no Gradle, mas a `MainActivity` está no pacote `com.fatec.merge_skills_kmp`. Isso cria uma armadilha: o atalho `.MainActivity` no manifest resolve para `com.fatec.merge_skills_kmp.android.MainActivity` — classe que não existe — causando `ClassNotFoundException` no Android.

A correção é usar o **nome totalmente qualificado**:

```xml title="composeApp/src/androidMain/AndroidManifest.xml"
<activity
    android:name="com.fatec.merge_skills_kmp.MainActivity"
    android:exported="true">
```

:::danger Não use `.MainActivity` aqui
O atalho com ponto só funciona quando o pacote da classe é igual ao `namespace` do módulo. Como aqui são diferentes, o nome completo é obrigatório.
:::
