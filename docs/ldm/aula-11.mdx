# Aula 11: A máquina de estados da impressão

## 📖 Conceito

Esta aula fecha o **Módulo 4 — Estado e persistência**, e fecha com a classe onde tudo que a trilha construiu até aqui se encontra. `EtiquetaViewModel` lê configuração através de `LabelStore` (aulas 09–10), passa o `LabelDocument` (aula 04) por uma função de renderizar que devolve bytes (`EscPosRenderer`, aula 05), e entrega esses bytes a um `PrinterTransport` (aula 06, implementado nas aulas 07 e 08). O assunto próprio desta classe não é nenhuma dessas três coisas — é o **estado**: o que a UI mostra enquanto a impressão acontece, e os invariantes que impedem essa UI de ficar presa.

O estado é `sealed interface EstadoImpressao`, com seis variantes: `Ocioso`, `Renderizando`, `Conectando`, `Enviando`, `Sucesso`, `Falha(erro)`. O caminho feliz visível por quem está coletando `estado: StateFlow<EstadoImpressao>` é `Ocioso → Renderizando → Conectando → Sucesso`. Repare no que falta nessa lista: `Enviando` está no enum, mas nenhum coletor jamais o vê. O motivo está na assinatura de `PrinterTransport.imprimir` (aula 06) — ela abre a conexão, escreve e fecha numa chamada `suspend` só. Não há um ponto de suspensão *entre* "conectou" e "escreveu" que o código possa aproveitar para trocar o estado no meio; a única coisa que `imprimir()` faz depois de `_estado.value = EstadoImpressao.Conectando` é chamar `transporte.imprimir(...)` e esperar o resultado — sucesso ou exceção. `Enviando` existe no enum porque é um estado conceitualmente real (a impressora está recebendo bytes), mas ele não tem um instante próprio no código para ser atribuído. E faz sentido que seja `Conectando` o estado que fica visível durante toda a chamada: é a fase que de fato falha — a LT-8359 hiberna sozinha depois de alguns minutos parada, e é a tentativa de conectar com ela dormindo que produz o erro que a UI precisa mostrar.

A segunda peça é a **guarda de reentrância**, no início de `imprimir()`. A UI desabilita o botão IMPRIMIR enquanto uma impressão está em andamento — mas esse botão é só um dos três pontos de entrada para `imprimir()`. Os outros dois são reimprimir uma etiqueta da lista de salvas e disparar a etiqueta de teste na tela de configurações (ambas na aula 13), e nem todos esses pontos têm um botão para desabilitar. Sem a guarda, duas chamadas concorrentes a `imprimir()` — por exemplo o usuário tocando "reimprimir" duas vezes rápido — mandariam o transporte escrever duas vezes, e isso não é um bug abstrato: é papel de verdade saindo da impressora em dobro.

A terceira peça é o parâmetro `salvarRascunho: Boolean = false`. Ele só deve ser `true` quando o `documento` passado para `imprimir()` é exatamente o que o usuário está digitando na tela Compor naquele momento. Reimprimir uma etiqueta salva da lista, ou disparar a etiqueta de teste das configurações, chama `imprimir()` com um documento que **não é** o rascunho do usuário — e se essas chamadas gravassem por cima dele, um toque em "reimprimir" apagaria o que a pessoa estava compondo em outra aba.

private class StoreFalsa(
    private val config: Configuracoes = Configuracoes("00:11:22", "KPrinter", avancoFinalMm = 3),
) : LabelStore {
    var rascunhoSalvo: LabelDocument? = null
    override fun configuracoes(): Flow<Configuracoes> = MutableStateFlow(config)
    override fun etiquetasSalvas(): Flow<List<EtiquetaSalva>> = flowOf(emptyList())
    override suspend fun salvarConfiguracoes(configuracoes: Configuracoes) = Unit
    override suspend fun salvarEtiqueta(nome: String, documento: LabelDocument): Long = 1L
    override suspend fun excluirEtiqueta(id: Long) = Unit
    override suspend fun salvarRascunho(documento: LabelDocument) { rascunhoSalvo = documento }
    override suspend fun carregarRascunho(): LabelDocument? = null
}

private class TransporteFalso(
    private val falhasAntesDeAceitar: Int = 0,
    private val erro: ErroImpressao = ErroImpressao.FalhaAoConectar("dormindo"),
) : PrinterTransport {
    var tentativas = 0
    var bytesRecebidos: ByteArray? = null
    override suspend fun listarDestinos() = listOf(PrinterTarget("00:11:22", "KPrinter"))
    override suspend fun imprimir(destino: PrinterTarget, bytes: ByteArray) {
        tentativas++
        if (tentativas <= falhasAntesDeAceitar) throw erro
        bytesRecebidos = bytes
    }
}

            var chamadas = 0
            override suspend fun listarDestinos(): List<PrinterTarget> = emptyList()
            override suspend fun imprimir(destino: PrinterTarget, bytes: ByteArray) {

                if (chamadas == 1) vm.imprimir(documento)

        vm.imprimir(documento, salvarRascunho = true)
        assertEquals(1, transporte.chamadas)
        assertIs<EstadoImpressao.Sucesso>(vm.estado.value)

Treze testes — o maior arquivo de teste da trilha inteira. Nenhum deles fala com hardware nem com banco de verdade: `StoreFalsa` implementa `LabelStore` guardando o que recebe em memória, e `TransporteFalso` implementa `PrinterTransport` contando tentativas e lançando o erro que o teste pedir. É esse par de dublês que permite exercitar a máquina de estados inteira — retry, guarda de reentrância, o rascunho não sendo sobrescrito — sem um socket Bluetooth ou uma porta serial reais. Repare em particular nos dois últimos testes: `reportarFalha nao sobrescreve uma impressao em andamento` e `chamada reentrante feita durante o envio e ignorada pela guarda` constroem o `TransporteFalso` como um `object` que chama de volta no próprio `vm` — `reportarFalha` ou `imprimir` — de **dentro** de `imprimir(destino, bytes)`. Isso simula a reentrância no cenário real: uma segunda chamada chegando enquanto a primeira ainda está no meio do call stack, não depois dela terminar.

## Passo 1 — EtiquetaViewModel

```kotlin title="shared/src/commonMain/kotlin/com/fatec/printec/ui/EtiquetaViewModel.kt"
package com.fatec.printec.ui

import com.fatec.printec.dados.LabelStore
import com.fatec.printec.etiqueta.LabelDocument
import com.fatec.printec.impressao.ErroImpressao
import com.fatec.printec.impressao.PrinterTarget
import com.fatec.printec.impressao.PrinterTransport
import kotlinx.coroutines.CancellationException
import kotlinx.coroutines.delay
import kotlinx.coroutines.flow.MutableStateFlow
import kotlinx.coroutines.flow.StateFlow
import kotlinx.coroutines.flow.asStateFlow
import kotlinx.coroutines.flow.first

sealed interface EstadoImpressao {
    data object Ocioso : EstadoImpressao
    data object Renderizando : EstadoImpressao
    data object Conectando : EstadoImpressao
    data object Enviando : EstadoImpressao
    data object Sucesso : EstadoImpressao
    data class Falha(val erro: ErroImpressao) : EstadoImpressao
}

class EtiquetaViewModel(
    private val store: LabelStore,
    private val transporte: PrinterTransport,
    private val renderizar: (LabelDocument, Int) -> ByteArray,
) {
    private val _estado = MutableStateFlow<EstadoImpressao>(EstadoImpressao.Ocioso)
    val estado: StateFlow<EstadoImpressao> = _estado.asStateFlow()

    /**
     * Chamado ao trocar de tela. Sem isto, o estado e global ao ViewModel e a
     * mensagem de uma reimpressao feita na aba "Salvas" reaparece na tela de
     * composicao, atribuida a um documento que nao tem nada a ver com ela.
     * So limpa estados terminais — nunca interrompe uma impressao em andamento.
     */
    fun limparEstadoSeConcluido() {
        val atual = _estado.value
        if (atual is EstadoImpressao.Sucesso || atual is EstadoImpressao.Falha) {
            _estado.value = EstadoImpressao.Ocioso
        }
    }

    /**
     * Registra uma falha que aconteceu FORA de [imprimir] -- hoje, so
     * TelaConfiguracoes ao listar destinos(). Sem isto, uma permissao de
     * Bluetooth negada faz a lista de impressoras aparecer vazia sem
     * explicacao nenhuma: NENHUM erro tipado chega a StatusImpressao, entao
     * o botao "Conceder permissao" nunca aparece e o primeiro uso empaca.
     *
     * Nao sobrescreve um estado "em andamento" -- essa checagem existe para
     * o caso de a tela Ajustes recarregar destinos() (ex.: reabrir a aba)
     * enquanto uma impressao disparada de outra aba ainda esta rodando no
     * escopo do app; a falha em listar impressoras nao pode apagar o status
     * visivel dessa impressao.
     */
    fun reportarFalha(erro: ErroImpressao) {
        val emAndamento = _estado.value
        if (emAndamento is EstadoImpressao.Renderizando ||
            emAndamento is EstadoImpressao.Conectando ||
            emAndamento is EstadoImpressao.Enviando
        ) return
        _estado.value = EstadoImpressao.Falha(erro)
    }

    /**
     * @param documento o que imprimir — vem do chamador, nunca do proprio
     *   ViewModel. Reimprimir uma etiqueta salva ou disparar a etiqueta de
     *   teste nao pode sobrescrever o que o usuario esta compondo na outra
     *   tela (ver [salvarRascunho]).
     * @param salvarRascunho so `true` quando [documento] E o que o usuario
     *   estava digitando na tela Compor. Reimpressao pela lista de salvas e a
     *   etiqueta de teste imprimem um documento que NAO e o rascunho do
     *   usuario e por isso nao podem gravar por cima dele.
     */
    suspend fun imprimir(documento: LabelDocument, salvarRascunho: Boolean = false) {
        // Guarda de reentrancia. A UI desabilita o botao IMPRIMIR, mas ha mais
        // de um ponto de entrada — compor, reimprimir pela lista de salvas, e a
        // etiqueta de teste nas configuracoes — e nem todos tem botao para
        // desabilitar. Duas impressoes concorrentes gastam papel de verdade.
        //
        // O estado e marcado Renderizando ANTES de qualquer suspensao —
        // inclusive a leitura de configuracoes() logo abaixo. Se a marcacao
        // esperasse a config chegar, duas chamadas concorrentes fariam a
        // checagem acima antes que qualquer uma delas marcasse o estado, e as
        // duas passariam pela guarda.
        val emAndamento = _estado.value
        if (emAndamento is EstadoImpressao.Renderizando ||
            emAndamento is EstadoImpressao.Conectando ||
            emAndamento is EstadoImpressao.Enviando
        ) return
        _estado.value = EstadoImpressao.Renderizando

        // Le configuracoes() so DEPOIS de reivindicar Renderizando (ver acima),
        // mas ainda assim precisa de try/catch: e I/O real (garantirConfiguracao
        // + mapToOne, que lanca se a linha nao existir) e, sem isto, um erro
        // aqui deixaria o estado preso em Renderizando para sempre -- a guarda
        // de reentrancia rejeitaria toda chamada seguinte e
        // limparEstadoSeConcluido() so limpa estados terminais.
        val config = try {
            store.configuracoes().first()
        } catch (e: CancellationException) {
            throw e   // cancelamento nao e erro de impressao
        } catch (e: ErroImpressao) {
            _estado.value = EstadoImpressao.Falha(e)
            return
        } catch (e: Exception) {
            _estado.value = EstadoImpressao.Falha(
                ErroImpressao.FalhaAoPreparar(e.message ?: e::class.simpleName.orEmpty()),
            )
            return
        }

        val id = config.impressoraId
        if (id.isNullOrBlank()) {
            _estado.value = EstadoImpressao.Falha(ErroImpressao.NenhumaImpressoraSelecionada)
            return
        }

        val umaCopia = try {
            // O rascunho e salvo na impressao, nao a cada tecla — e somente
            // quando quem chamou pediu (ver documentacao do parametro acima).
            if (salvarRascunho) store.salvarRascunho(documento)
            renderizar(documento, config.avancoFinalMm)
        } catch (e: CancellationException) {
            throw e   // cancelamento nao e erro de impressao
        } catch (e: ErroImpressao) {
            _estado.value = EstadoImpressao.Falha(e)
            return
        } catch (e: Exception) {
            // Nada pode escapar daqui sem virar estado. Uma excecao crua
            // deixaria a UI presa em "Renderizando" para sempre, sem caminho
            // para Falha e sem o usuario poder tentar de novo.
            _estado.value = EstadoImpressao.Falha(
                ErroImpressao.FalhaAoPreparar(e.message ?: e::class.simpleName.orEmpty()),
            )
            return
        }
        val payload = ByteArray(umaCopia.size * documento.copias.coerceAtLeast(1))
        repeat(documento.copias.coerceAtLeast(1)) { i ->
            umaCopia.copyInto(payload, destinationOffset = i * umaCopia.size)
        }

        val destino = PrinterTarget(id, config.impressoraNome ?: id)

        // Retry unico: a LT-8359 costuma acordar na primeira tentativa e
        // aceitar a segunda. Mais que isso so faria o usuario esperar.
        repeat(2) { tentativa ->
            // So Conectando: o transporte conecta e escreve numa chamada so,
            // entao nao ha suspensao entre marcar Conectando e marcar Enviando
            // -- nenhum coletor jamais veria o estado intermediario. Conectar
            // e a fase que de fato falha (impressora hibernada), entao e ela
            // que fica visivel durante toda a chamada.
            _estado.value = EstadoImpressao.Conectando
            try {
                transporte.imprimir(destino, payload)
                _estado.value = EstadoImpressao.Sucesso
                return
            } catch (e: ErroImpressao) {
                val ultima = tentativa == 1
                val naoAdiantaRepetir = e !is ErroImpressao.FalhaAoConectar
                if (ultima || naoAdiantaRepetir) {
                    _estado.value = EstadoImpressao.Falha(e)
                    return
                }
                // A impressora hibernada tem mais chance de ter acordado se
                // damos um instante antes de repetir. Tentar de novo no mesmo
                // instante e o pior caso justamente para esse cenario -- e e
                // essa politica que o teste de hardware vai avaliar.
                delay(1_000)
            } catch (e: CancellationException) {
                throw e
            } catch (e: Exception) {
                // Nada nao-tipado pode escapar do laco de envio: uma excecao
                // crua aqui deixaria a UI presa em "Conectando" para sempre.
                _estado.value = EstadoImpressao.Falha(
                    ErroImpressao.FalhaAoEscrever(e.message ?: e::class.simpleName.orEmpty()),
                )
                return
            }
        }
    }
}
```

Quatro partes valem uma leitura separada.

**A guarda de reentrância** abre `imprimir()`. Ela lê `_estado.value` uma vez e, se ele já é `Renderizando`, `Conectando` ou `Enviando` — qualquer estado "em andamento", não só um deles —, a função simplesmente retorna sem fazer nada. Logo em seguida, ainda antes de qualquer `suspend fun` ser chamada, `_estado.value` é atribuído a `EstadoImpressao.Renderizando`. Essa ordem — checar e marcar, as duas de forma síncrona, antes da primeira suspensão real — é o que faz a guarda funcionar contra uma chamada reentrante que chega no meio da execução da primeira, e não só contra uma chamada que chega depois dela terminar.

**A leitura de configurações** vem em seguida, e só depois de `Renderizando` já estar marcado. `store.configuracoes().first()` é I/O de verdade — a implementação real (`LabelStoreSqlDelight`, aula 10) roda `garantirConfiguracao()` e um `mapToOne` que lança se a linha não existir —, então está dentro de um `try` com três `catch`: `CancellationException` relançada, `ErroImpressao` tratado à parte (embora `configuracoes()` não declare lançar um, o `catch` cobre o caso de uma implementação futura de `LabelStore` que lance), e qualquer outra `Exception` convertida em `EstadoImpressao.Falha(ErroImpressao.FalhaAoPreparar(...))`. Sem impressora configurada (`config.impressoraId` nulo ou em branco), a função encerra em `Falha(NenhumaImpressoraSelecionada)` antes mesmo de tentar renderizar.

**A renderização com as cópias** salva o rascunho — só se `salvarRascunho` for `true` — e chama `renderizar(documento, config.avancoFinalMm)`, de novo dentro de um `try` com os mesmos três `catch`. O resultado é os bytes de **uma** etiqueta; o `payload` final é um `ByteArray` do tamanho de `umaCopia.size * copias`, preenchido copiando `umaCopia` para dentro dele `copias` vezes com `copyInto`. É por isso que o teste `as copias resultam em um envio por copia numa conexao logica` vê `transporte.tentativas == 1` mesmo com três cópias: o transporte recebe um `payload` já concatenado numa única chamada — a "conexão lógica" do nome do teste — não três chamadas separadas.

**O laço de envio com retry** é o `repeat(2) { tentativa -> ... }` final. A cada iteração, `_estado.value` é marcado `Conectando` e `transporte.imprimir(destino, payload)` é chamado. Sucesso marca `Sucesso` e retorna. Uma `ErroImpressao` calcula duas condições — `ultima` (é a segunda iteração, `tentativa == 1`) e `naoAdiantaRepetir` (o erro não é `FalhaAoConectar`) — e só tenta de novo se nenhuma das duas for verdadeira; caso contrário marca `Falha` e retorna imediatamente. Entre uma tentativa e a próxima, `delay(1_000)`. `CancellationException` é sempre relançada, nunca vira `Falha`. Qualquer outra `Exception` não tipada vira `Falha(FalhaAoEscrever(...))` e a função retorna — sem tentar de novo, porque o tipo dessa exceção é desconhecido e insistir não tem garantia nenhuma de ajudar.

## ⚠️ Atenção

Três invariantes que o código defende explicitamente, cada um com o comentário que documenta por que a ordem importa:

1. **`Renderizando` é marcado antes de qualquer suspensão**, inclusive antes de ler `configuracoes()`. Se a marcação esperasse a config chegar, duas chamadas concorrentes fariam a checagem da guarda antes que qualquer uma delas tivesse marcado o estado — e as duas passariam.
2. **Nada não tipado escapa.** Todo `catch (e: Exception)` — há três no arquivo — vira um `EstadoImpressao.Falha`. Uma exceção crua deixaria a UI presa em "Renderizando" ou "Conectando" para sempre, e a guarda de reentrância rejeitaria toda chamada seguinte, porque `limparEstadoSeConcluido()` só limpa estados terminais (`Sucesso` e `Falha`) — nunca um estado "em andamento".
3. **`CancellationException` é relançada, sempre.** Cancelamento não é erro de impressão; tratá-lo como `Falha` quebraria o comportamento de corrotinas do resto do app — quem cancelou o escopo esperaria a `CancellationException` se propagar, não ver um estado de falha aparecer no meio do caminho.

E o retry: `repeat(2)` são no máximo duas tentativas — uma original e **uma** repetição —, e só se repete quando o erro é `ErroImpressao.FalhaAoConectar`. Qualquer outro tipo de `ErroImpressao` (`PermissaoNegada`, `NaoPareada`, `FalhaAoEscrever`) vai direto para `Falha` na primeira tentativa. A lógica por trás é a mesma explicada no comentário do código: a impressora hibernada tem mais chance de ter acordado se o app espera um segundo antes de tentar de novo; insistir no mesmo instante é o pior caso justamente para esse cenário, e é o cenário que o `delay(1_000)` existe para tratar. Repetir uma `PermissaoNegada` ou uma `NaoPareada` não resolveria nada — o segundo em espera não muda se o app tem a permissão ou se o dispositivo está pareado.
